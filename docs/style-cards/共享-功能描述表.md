# 共享功能描述表：X 推文互动回复器 v2.3.0

> 用途：`docs/使用说明书.md` 与 `docs/开发概要说明书.md` 共用同一套模块划分、编号与术语。
> 口径来源：manifest.json、background.js、content.js、options.js、content.css 实测。
> 版本：v2.3.0。改动时两份文档同步更新。

## 表1 功能描述表

| 模块名称 | 功能要点 | 关键需求 |
|---|---|---|
| 设置管理 | 8 个 API 渠道独立配置 Key、模型、Base URL；API Key 可见性切换；回复参数与调试开关保存 | 每个渠道单独缓存，切换不互相覆盖；保存前校验 Key 与 Base URL |
| 接口调度 | 接收页面请求，读取设置，选定渠道与协议，拼装提示词，发起 LLM 请求 | 统一返回候选数组；HTML/非 JSON 响应按配置错误抛出，不退化为兜底句 |
| Base URL 归一化 | 根域名、带版本段、完整 endpoint、末尾 `#` 四类输入归一到真实请求地址 | 设置页预览地址与实际请求地址必须一致，双端实现同步 |
| 推文抓取与语言识别 | 从推文节点或回复弹窗抽取正文、作者、handle、链接，判定主语言 | 语言判定纯靠字符正则，不依赖用户手选 |
| 按钮注入 | 推文操作区注入 `AI回`，回复编辑器旁的工具栏注入 `AI填入` | MutationObserver + 滚动 + 多轮延时扫描；按钮与推文身份一一对应，不重复注入 |
| 候选生成与清洗 | 一次生成 3 条候选，最多 3 轮重试；解析 JSON 数组或编号文本 | 命中禁用词、重复、乱码、空内容、尾部截断的候选整条丢弃 |
| 图片理解 | 抓取推文图片，下载转 base64，按渠道拼多模态入参 | 默认读 3 张、上限 4 张；单张超 5MB 跳过；渠道拒绝图片时退回纯文本 |
| 草稿窗与填入 | 560px 面板展示 3 条候选，每条独立编辑、复制、填入 X | 永不自动发送；填入不硬替换编辑器根节点 |

## 术语表

| 术语 | 含义 |
|---|---|
| 候选 | 模型生成的一条可发布回复文本，草稿窗内最多 3 条 |
| 草稿窗 | 页面右下角固定面板，class 前缀 `akiii-draft-` |
| `AI回` | 时间线与详情页操作区的生成按钮 |
| `AI填入` | 回复编辑器工具栏旁的生成按钮 |
| 渠道 | 设置页「接口类型」中的一项，共 8 项 |
| 协议 | 请求体与鉴权风格，渠道到协议的映射见开发概要 3.2.1 |
| 归一化 | 把用户填写的 Base URL 补全为完整请求地址的过程 |
